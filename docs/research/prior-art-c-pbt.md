# Prior art: property-based testing in C

Research for ticket `02-research-prior-art-c-pbt`. Surveyed 2026-09-09. Every claim cites the primary source (README, source file, header, or repository metadata) it was read from.

## Lessons for qc

1. **Nobody in C has shipped the combination qc wants.** theft is the only mature C library with shrinking *and* crash tolerance, and it is POSIX-only and unmaintained since 2019/2020. Every other C library either has no shrinking (quickcheck4c, mcandre/qc), no crash tolerance (qcc, tapc), or catches segfaults in-process with `siglongjmp` (foobarbaz), which leaves the process in an undefined state. DeepState isolates crashes on both Unix and Windows but is a fuzzing harness with no in-library shrinking.
2. **Draw-based APIs already exist in C and they work.** skhoroshavin/qcc (2017) draws inside the test body with `GIVEN_UINT(name, in_range, 1, 100)` and records every draw as an interval on a stream; tapc (2026) reads `tap_read_int32()` from an implicit byte stream and records a chunk table; Hegel's C ABI does `hegel_generate_integer(ctx, tc, min, max, &out)`. All three shrink by editing the recorded stream and re-running the generator, which is exactly the Hypothesis model in `CONTEXT.md`. theft's `alloc` callback plus `theft_random_bits` is the same idea with a callback-shaped API.
3. **theft's autoshrink is the closest existing C shrinker and its limits are instructive.** It records bit-request sizes but not types, so its mutations (drop, shift, mask, swap, subtract) are blind byte surgery with a learned weighting, and it requires that "a bitstream of all `0` bits should produce a minimal value for the type". A typed choice sequence (qc's plan) removes that constraint and lets the shrinker pick type-aware moves like tapc's per-chunk strategies.
4. **The worker protocol should carry a verdict, not just an exit status.** theft's worker writes one result byte down a pipe and the supervisor treats "closed without response" as a crash, which is then reported as a plain `FAIL` indistinguishable from an assertion failure. Proptest's worker appends every test-case outcome to a replay file so the supervisor can restart a crashed worker and replay past its last known position; DeepState reserves distinct exit codes for pass/fail/crash/abandon. qc should distinguish crash, timeout, and property failure in its report.
5. **`fork()` is the wrong primitive for Windows; spawn-self-and-replay is the portable shape.** Proptest (via rusty-fork) and DeepState's Win32 path both re-spawn the current executable with arguments naming the test, then read a verdict back, because "true process forking can be done on Windows, it's neither fast nor reliable". theft's `fork()`+`pipe()`+`poll()` design is why it fails to compile under MSVC (open issue #62, `pid_t` unknown).
6. **Timeouts need a two-stage kill and a decision about "handled the signal and passed".** theft sends the configured signal (default `SIGTERM`), waits `exit_timeout` (100 ms), then `SIGKILL`s; a child that catches the signal and exits with `EXIT_SUCCESS` still counts as a pass. Proptest fails a case that exceeds `timeout` even if it eventually returned.
7. **Reproduction strings and persisted regressions are table stakes in RapidCheck and Proptest.** RapidCheck prints an opaque `reproduce=` string that skips straight to the minimal case; Proptest writes `proptest-regressions/*.txt` seed files meant to be committed. Hegel calls the same thing a "reproduce blob" (base64 choice sequence). qc's choice sequence is exactly this artefact and should be printable and replayable from day one.
8. **macOS CrashReporter makes crash-shrinking slow.** theft documents that "the CrashReporter on macOS slows down shrinking by several orders of magnitude, as it logs information for every single crashing process". qc's macOS worker should consider suppressing crash reporting (or catching the signal in the worker and exiting cleanly with a crash verdict) to keep shrinking fast.

## theft (Scott Vokes)

Repository: https://github.com/silentbicycle/theft

**How properties are declared.** A property is a plain C function taking `struct theft *t` and one to seven `void *` arguments, returning `THEFT_TRIAL_PASS`, `THEFT_TRIAL_FAIL`, `THEFT_TRIAL_SKIP`, or `THEFT_TRIAL_ERROR` ([doc/usage.md](https://github.com/silentbicycle/theft/blob/master/doc/usage.md)). The arity is fixed by which of `.prop1` … `.prop7` is set in `struct theft_run_config`, whose `type_info[THEFT_MAX_ARITY]` array must match; `THEFT_MAX_ARITY` is 7 and `THEFT_DEF_TRIALS` is 100 ([inc/theft_types.h](https://github.com/silentbicycle/theft/blob/master/inc/theft_types.h)). The run is started with `enum theft_run_res theft_run(const struct theft_run_config *cfg)` ([inc/theft.h](https://github.com/silentbicycle/theft/blob/master/inc/theft.h)). The config also carries `seed`, `trials`, `always_seeds`, `bloom_bits`, a `.fork` sub-struct, and a `.hooks` struct with `run_pre/run_post`, `gen_args_pre`, `trial_pre/trial_post`, `counterexample`, `shrink_pre/shrink_post/shrink_trial_post`, and `fork_post` callbacks ([doc/usage.md](https://github.com/silentbicycle/theft/blob/master/doc/usage.md), [inc/theft_types.h](https://github.com/silentbicycle/theft/blob/master/inc/theft_types.h)).

**How values are generated.** Each argument has a `struct theft_type_info` with callbacks: `alloc` (required), `free`, `hash`, `print`, `shrink`, plus `autoshrink_config` and an opaque `env` ([inc/theft_types.h](https://github.com/silentbicycle/theft/blob/master/inc/theft_types.h)). `alloc` has the signature `enum theft_alloc_res theft_alloc_cb(struct theft *t, void *env, void **instance)` and builds the value "based off of the random bit stream" using `theft_random_bits(t, bit_count)`, `theft_random_bits_bulk(t, bit_count, buffer)`, or `theft_random_choice(t, LIMIT)` ([doc/usage.md](https://github.com/silentbicycle/theft/blob/master/doc/usage.md)). `theft_random_bits` is declared as `uint64_t theft_random_bits(struct theft *t, uint8_t bits)` ([inc/theft.h](https://github.com/silentbicycle/theft/blob/master/inc/theft.h)). The runner seeds the PRNG per trial (`theft_random_set_seed(t, trial_info.seed)`) and, when every argument is hashable, deduplicates already-tried argument combinations through a bloom filter (`t->bloom = theft_bloom_init(NULL)`; `theft_call_check_called`) ([src/theft_run.c](https://github.com/silentbicycle/theft/blob/master/src/theft_run.c)). The README notes it bundles a Mersenne Twister PRNG and FNV-1a hashing ([README.md](https://github.com/silentbicycle/theft/blob/master/README.md)).

**How shrinking works.** Two modes.

*Manual:* the `shrink` callback `enum theft_shrink_res theft_shrink_cb(struct theft *t, const void *instance, uint32_t tactic, void *env, void **output)` is called with an increasing integer `tactic`; it returns `THEFT_SHRINK_OK`, `THEFT_SHRINK_DEAD_END`, `THEFT_SHRINK_NO_MORE_TACTICS`, or `THEFT_SHRINK_ERROR` ([inc/theft_types.h](https://github.com/silentbicycle/theft/blob/master/inc/theft_types.h)). Tactics "should be ordered so tactics that remove more information are tried first" and "Successful shrinking steps reset the tactic counter to 0" ([doc/shrinking.md](https://github.com/silentbicycle/theft/blob/master/doc/shrinking.md)). The loop in `theft_shrink.c` iterates `for (uint32_t tactic = 0; tactic < THEFT_MAX_TACTICS; tactic++)`, treats `DEAD_END` as "try next tactic" and `NO_MORE_TACTICS` as finished ([src/theft_shrink.c](https://github.com/silentbicycle/theft/blob/master/src/theft_shrink.c)).

*Autoshrink (since v0.3.0):* theft can "save the random bitstream used to generate the argument instance, and re-run the property test while simplifying the bitstream", an implementation "loosely based on a design described by David R. MacIver"; it requires that "when `theft_random_bits` return smaller values, it should lead to a simpler generated result. In particular, a bitstream of all `0` bits should produce a minimal value for the type", and "Modifications to the bit pool during auto-shrinking are aligned to those requests' bits"; with autoshrink enabled the `shrink` and `hash` callbacks must not be defined ([doc/shrinking.md](https://github.com/silentbicycle/theft/blob/master/doc/shrinking.md)). The pool struct records `bits`, `consumed`, and a `requests` array of request sizes; the actions are `ASA_DROP`, `ASA_SHIFT`, `ASA_MASK`, `ASA_SWAP`, `ASA_SUB`, and the default is to stop after `DEF_MAX_FAILED_SHRINKS` (100) unsuccessful shrinks in a row ([src/theft_autoshrink.h](https://github.com/silentbicycle/theft/blob/master/src/theft_autoshrink.h)). `drop_from_bit_pool` drops whole requests (or, for requests over 64 bits, a sub-range) with probability governed by `DEF_DROP_BITS`; `choose_and_mutate_request` applies shift/mask/swap/subtract to a single request's bits; trailing zero bytes are truncated; an `autoshrink_model` reweights the actions based on which ones produced progress (`theft_autoshrink_update_model`) ([src/theft_autoshrink.c](https://github.com/silentbicycle/theft/blob/master/src/theft_autoshrink.c)). After the pool is exhausted the reader "just return[s] 0 bits forever and stop[s] tracking requests" ([src/theft_autoshrink.c](https://github.com/silentbicycle/theft/blob/master/src/theft_autoshrink.c)).

**Crashing test cases.** Optional, via `.fork = { .enable, .timeout /* ms */, .signal /* default SIGTERM */ }` plus `exit_timeout` (default `THEFT_DEF_EXIT_TIMEOUT_MSEC`, 100 ms) ([doc/forking.md](https://github.com/silentbicycle/theft/blob/master/doc/forking.md), [inc/theft_types.h](https://github.com/silentbicycle/theft/blob/master/inc/theft_types.h)). Implementation in `theft_call`: per trial, `pipe()` then `fork()` (retrying on `EAGAIN` with exponential `nanosleep` backoff up to `MAX_FORK_RETRIES`); the child runs the optional `fork_post` hook, calls the property, writes one byte `(uint8_t)res` to the pipe, and exits `EXIT_SUCCESS` only if the result was `PASS`; the parent `poll()`s the pipe with the configured timeout and reads one byte; `rd == 0` is commented "closed without response -> crashed" and mapped to `THEFT_TRIAL_FAIL` ([src/theft_call.c](https://github.com/silentbicycle/theft/blob/master/src/theft_call.c)). On timeout the parent does `kill(pid, kill_signal)`, waits `exit_timeout` for the child to exit, then sends `SIGKILL` and waits a further 10 ms; "If the child still exited successfully, then consider it a PASS, even though it exceeded the timeout", otherwise `FAIL` ([src/theft_call.c](https://github.com/silentbicycle/theft/blob/master/src/theft_call.c)). Documented consequences: "changes to memory in the child process will not be visible to the parent process, due to copy-on-write" and "the CrashReporter on macOS slows down shrinking by several orders of magnitude, as it logs information for every single crashing process" ([doc/forking.md](https://github.com/silentbicycle/theft/blob/master/doc/forking.md)). The `fork_post` hook is intended for "Dropping privileges with setrlimit, pledge, etc. on the forked child process before running the property" ([doc/usage.md](https://github.com/silentbicycle/theft/blob/master/doc/usage.md)). Note that a crash and an ordinary property failure both surface as `THEFT_TRIAL_FAIL`; there is no distinct crash verdict in `enum theft_trial_res` ([inc/theft_types.h](https://github.com/silentbicycle/theft/blob/master/inc/theft_types.h)).

**Windows support.** None. The README states theft "does not depend on anything beyond C99 and a Unix-like environment" ([README.md](https://github.com/silentbicycle/theft/blob/master/README.md)); the Makefile compiles with `-std=c99 -D_POSIX_C_SOURCE=199309L` ([Makefile](https://github.com/silentbicycle/theft/blob/master/Makefile)); the call path uses `fork`, `pipe`, `poll`, `waitpid`, `kill`, `nanosleep`, and `<sys/time.h>` ([src/theft_call.c](https://github.com/silentbicycle/theft/blob/master/src/theft_call.c)); internal types include `<sys/types.h>` for `pid_t` ([src/theft_types_internal.h](https://github.com/silentbicycle/theft/blob/master/src/theft_types_internal.h)). Open issue #62 "MSVC and clang-cl compilation errors" (opened 2025-03-12, no maintainer response) reports `unknown type name 'pid_t'` in `theft_types_internal.h` and a variable-length array (`left_pad`) rejected by MSVC ([issue #62](https://github.com/silentbicycle/theft/issues/62)).

**Licence.** ISC, "Copyright (c) 2014-19 Scott Vokes" ([LICENSE](https://github.com/silentbicycle/theft/blob/master/LICENSE)). (oz123/awesome-c mislabels it MIT: [awesome-c README](https://github.com/oz123/awesome-c/blob/master/README.md).)

**Maintenance status.** Last tagged version v0.4.5 on 2019-02-11 ([tags](https://github.com/silentbicycle/theft/tags), [CHANGELOG.md](https://github.com/silentbicycle/theft/blob/master/CHANGELOG.md)); no GitHub Releases ([releases](https://github.com/silentbicycle/theft/releases)); last push 2020-12-17, 31 open issues, 652 stars, not archived ([GitHub API](https://api.github.com/repos/silentbicycle/theft)).

## quickcheck4c (Andrea Zito)

Repository: https://github.com/nivox/quickcheck4c

**Properties.** A property is `QCC_TestStatus prop(QCC_GenValue **vals, int len, QCC_Stamp **stamp)`; values are read by index and type with `*QCC_getValue(vals, 0, int*)`; the runner is the variadic `int QCC_testForAll(int num, int maxFail, QCC_property prop, int genNum, ...)` taking generator function pointers, e.g. `QCC_testForAll(100, 1000, mulCommutativity, 2, QCC_genInt, QCC_genInt)` ([README.md](https://github.com/nivox/quickcheck4c/blob/master/README.md), [quickcheck4c.h](https://github.com/nivox/quickcheck4c/blob/master/quickcheck4c.h)). `QCC_TestStatus` is `{ QCC_OK=1, QCC_FAIL=0, QCC_NOTHING=-1 }` ([quickcheck4c.h](https://github.com/nivox/quickcheck4c/blob/master/quickcheck4c.h)). `QCC_Stamp` labels support "Categorization of test case via labels for coverage statistics" ([README.md](https://github.com/nivox/quickcheck4c/blob/master/README.md)).

**Generation.** Generators return a heap `QCC_GenValue { void *value; int n; QCC_showValue show; QCC_freeValue free; }`; built-ins cover `long, int, double, float, boolean, char` and arrays/strings, with ranged variants such as `QCC_genArrayIntLR(int len, int from, int to)` ([quickcheck4c.h](https://github.com/nivox/quickcheck4c/blob/master/quickcheck4c.h), [README.md](https://github.com/nivox/quickcheck4c/blob/master/README.md)). Randomness is `srandom(seed)` / `random()` from `QCC_init(int seed)` ([quickcheck4c.c](https://github.com/nivox/quickcheck4c/blob/master/quickcheck4c.c)).

**Shrinking.** None. The README lists "implement argument shrinking to find the smallest arguments set which falsifies a property" as possible future work ([README.md](https://github.com/nivox/quickcheck4c/blob/master/README.md)).

**Crashing test cases.** Not handled; no fork or signal code in the header or source ([quickcheck4c.h](https://github.com/nivox/quickcheck4c/blob/master/quickcheck4c.h), [quickcheck4c.c](https://github.com/nivox/quickcheck4c/blob/master/quickcheck4c.c)).

**Windows.** Not addressed. The only non-libc dependency is `random()`/`srandom()`, which are POSIX rather than C99 ([quickcheck4c.c](https://github.com/nivox/quickcheck4c/blob/master/quickcheck4c.c)).

**Licence.** BSD 3-Clause, "Copyright (c) 2014, Andrea Zito" ([LICENSE](https://github.com/nivox/quickcheck4c/blob/master/LICENSE), [README.md](https://github.com/nivox/quickcheck4c/blob/master/README.md)).

**Maintenance.** Archived; last push 2016-12-07; 25 stars ([GitHub API](https://api.github.com/repos/nivox/quickcheck4c)).

## qc (mcandre / Andrew Pennebaker)

Original repository `https://github.com/mcandre/qc` now returns 404 (both the [GitHub API](https://api.github.com/repos/mcandre/qc) and [raw README](https://raw.githubusercontent.com/mcandre/qc/master/README.md)). It is still listed in Bfgeshka/awesome-c as "mcandre/qc - C port of the QuickCheck unit test framework. BSD 2-Clause" ([awesome-c README](https://github.com/Bfgeshka/awesome-c/blob/master/README.md)). The fork https://github.com/weskerfoot/qc (last push 2014-03-06, [GitHub API](https://api.github.com/repos/weskerfoot/qc)) preserves the code; its licence file reads "FreeBSD License / Copyright 2012 Andrew Pennebaker" ([LICENSE.md](https://github.com/weskerfoot/qc/blob/master/LICENSE.md)) and the README points at `http://www.yellosoft.us/quickcheck` ([README.md](https://github.com/weskerfoot/qc/blob/master/README.md)).

**Properties.** `bool prop(blob data)` reading arguments with `qc_args(int, 0, int)`; run with `for_all(property, arglen, gs, ps, max_class)`, a macro over `bool _for_all(prop, size_t arglen, gen const gs[], print const ps[], size_t max_size)` ([qc.h](https://github.com/weskerfoot/qc/blob/master/qc.h), [example.c](https://github.com/weskerfoot/qc/blob/master/example.c)).

**Generation.** Generators are `void gen_int(blob data)` style functions writing via `qc_return(type, value)`; built-ins `gen_bool`, `gen_int`, `gen_char`, `gen_string`, `gen_array`; all values live in Boehm GC memory (`GC_MALLOC`, link `-lgc`) and randomness is `rand()` seeded from `time(NULL)` ([qc.h](https://github.com/weskerfoot/qc/blob/master/qc.h), [qc.c](https://github.com/weskerfoot/qc/blob/master/qc.c), [README.md](https://github.com/weskerfoot/qc/blob/master/README.md)).

**Shrinking.** None. `_for_all` runs a fixed 100 iterations, prints `*** Failed!` and the argument values on the first failure, and returns ([qc.c](https://github.com/weskerfoot/qc/blob/master/qc.c)).

**Crashing test cases.** Not handled ([qc.c](https://github.com/weskerfoot/qc/blob/master/qc.c)).

**Windows.** The README lists BoehmGC as a Windows requirement but there is no platform-specific code ([README.md](https://github.com/weskerfoot/qc/blob/master/README.md)).

**Licence / maintenance.** FreeBSD (BSD 2-Clause) ([LICENSE.md](https://github.com/weskerfoot/qc/blob/master/LICENSE.md)); the original repository is gone and the surviving fork was last pushed 2014-03-06 ([GitHub API](https://api.github.com/repos/weskerfoot/qc)).

## qcc (Sergey Khoroshavin)

Repository: https://github.com/skhoroshavin/qcc. README is the single line "QuickCheck for C" with Travis and AppVeyor badges ([README.md](https://github.com/skhoroshavin/qcc/blob/master/README.md)). This is the closest existing C design to qc's draw-based API.

**Properties.** `TEST(name)` expands to `static void name(struct qcc_context *_ctx)`; tests are grouped with `TEST_GROUP`, run with `RUN_TEST`/`RUN_GROUP`, and `TEST_MAIN()` defines `main` around `qcc_main(argc, argv, qcc_test_main)`. Inside the body, `ASSERT(cond)` calls `qcc_context_fail` and returns; `ASSUME(cond)` sets `_ctx->result = QCC_TEST_SKIP`; `FAIL(fmt, ...)` formats a message into an arena ([src/qcc.h](https://github.com/skhoroshavin/qcc/blob/master/src/qcc.h)). Results are `QCC_TEST_SUCCEED, QCC_TEST_FAIL, QCC_TEST_SKIP, QCC_TEST_OVERRUN` ([src/context.h](https://github.com/skhoroshavin/qcc/blob/master/src/context.h)).

**Generation (draw-based).** Values are drawn in the body: `GIVEN_UINT(name, cond, ...)` expands to `type name = qcc_generate_uint(qcc_gen_uint_##cond(_ctx, sizeof(type), ...))` followed by `qcc_context_register_param(_ctx, "%s: %" PRIu64, #name, name)` so the draw is printed on failure; conditions include `any`, `in_range`, `less_than`, `equal_to`, `from_array`; `GIVEN_UINT_ARRAY` draws arrays ([src/qcc_uint.h](https://github.com/skhoroshavin/qcc/blob/master/src/qcc_uint.h)). A generator is `struct qcc_generator { struct qcc_context *context; size_t type_size; qcc_generate_fn generate; }` with combinators `qcc_gen_one_of`, `qcc_gen_transform`, `qcc_gen_value_from` ([src/generator.h](https://github.com/skhoroshavin/qcc/blob/master/src/generator.h)). Every draw pulls a `qcc_uint` from a `struct qcc_stream`; `qcc_stream_begin`/`qcc_stream_end` push and pop intervals so each logical draw is recorded as an interval over the stream nodes, and reading past the end sets `is_overrun` ([src/stream.h](https://github.com/skhoroshavin/qcc/blob/master/src/stream.h), [src/stream.c](https://github.com/skhoroshavin/qcc/blob/master/src/stream.c)).

**Shrinking.** `_run_test_and_shrink` runs the test once on a fresh stream; on failure it loops over four stream transforms, `_stream_skip_interval`, `_stream_zero_interval`, `_stream_halve_interval`, `_stream_dec_interval`, applied to each recorded interval in turn, re-running the test on the edited stream and restarting the pass whenever a candidate still fails; it stops when a full pass makes no progress ([src/engine.c](https://github.com/skhoroshavin/qcc/blob/master/src/engine.c)). The engine defaults to `max_tries = 1000` and reports "No input was accepted by test as valid" if every case was skipped ([src/engine.c](https://github.com/skhoroshavin/qcc/blob/master/src/engine.c), [src/engine.h](https://github.com/skhoroshavin/qcc/blob/master/src/engine.h)).

**Crashing test cases.** Not handled; the test function is called directly in-process (`test_fn(&ctx)`) with no signal or process code ([src/engine.c](https://github.com/skhoroshavin/qcc/blob/master/src/engine.c)).

**Windows.** Yes. AppVeyor builds with `image: Visual Studio 2015` for Win32 and x64 via `cmake -G "Visual Studio 14 2015"` ([appveyor.yml](https://github.com/skhoroshavin/qcc/blob/master/appveyor.yml)); CMake adds `-std=c99 -Wall -Wextra -Werror` only `if(NOT MSVC)` and offers ASan/MSan/valgrind options ([CMakeLists.txt](https://github.com/skhoroshavin/qcc/blob/master/CMakeLists.txt)).

**Licence / maintenance.** MIT, "Copyright (c) 2017 Sergey Khoroshavin" ([LICENSE](https://github.com/skhoroshavin/qcc/blob/master/LICENSE)); last push 2017-03-26, 3 stars ([GitHub API](https://api.github.com/repos/skhoroshavin/qcc)).

## foobarbaz (Oderjunkie)

Repository: https://github.com/Oderjunkie/foobarbaz, "a single-header property-based testing library in C99" ([GitHub API](https://api.github.com/repos/Oderjunkie/foobarbaz)).

**Properties.** Mocha-style `describe ("add") { it ("is commutative") { int x, y; given (x, y) { assert(add(x, y) == add(y, x)); } } }`; the README notes "you can't write `given (int x, int y)` because of the limitations of C macros" ([README.md](https://github.com/Oderjunkie/foobarbaz/blob/master/README.md)).

**Generation.** `given(...)` is a macro loop that fills the raw bytes of each named variable: try 0 is `memset(ptr, 0x00, len)`, try 1 is `0xff`, then `rand() % CHAR_MAX` per byte, for up to `MAX_TRIES` (default 10000) ([foobarbaz.h](https://github.com/Oderjunkie/foobarbaz/blob/master/foobarbaz.h)). The README's footnote admits it "is not *completely* type-agnostic, because if a type has an 'invalid' state (ex. a tagged union) then the input may be invalid" ([README.md](https://github.com/Oderjunkie/foobarbaz/blob/master/README.md)).

**Shrinking.** After a failure `_iterate` enters `is_reducing` mode and applies one random byte mutation per step, chosen from right-shift, AND-mask, zero-and-shift, or subtract, keeping the mutated bytes if the property still fails and restoring the last failing bytes otherwise ([foobarbaz.h](https://github.com/Oderjunkie/foobarbaz/blob/master/foobarbaz.h)).

**Crashing test cases.** In-process only. With `#define CATCH_SEGFAULTS` ("requires POSIX") it installs a `sigaction` handler for `SIGSEGV` that `siglongjmp`s back to a `sigsetjmp` inside the `given` loop and marks the case failed ([README.md](https://github.com/Oderjunkie/foobarbaz/blob/master/README.md), [foobarbaz.h](https://github.com/Oderjunkie/foobarbaz/blob/master/foobarbaz.h)). No timeout, no fork.

**Windows.** The segfault path is POSIX-only; the rest is libc ([foobarbaz.h](https://github.com/Oderjunkie/foobarbaz/blob/master/foobarbaz.h)).

**Licence / maintenance.** GPL-3.0 ([LICENSE](https://github.com/Oderjunkie/foobarbaz/blob/master/LICENSE)); last push 2023-07-21, 8 stars ([GitHub API](https://api.github.com/repos/Oderjunkie/foobarbaz)).

## tapc (brenoleonhardt)

Repository: https://github.com/brenoleonhardt/tapc, "Minimal C99 TAP 13 library with property-based testing and automatic shrinking. STB-style single-header, no dependencies beyond libc." ([GitHub API](https://api.github.com/repos/brenoleonhardt/tapc)).

**Properties.** `bool prop(void *data)` plus a generator `void *gen(void)`, run by `int tap_check_property(bool (*prop)(void*), void* (*gen)(void), const char *desc, int iterations)`; failures are described with `TAP_FAIL_AT(fmt, ...)` and the result is one TAP `ok`/`not ok` line with a YAML block ([README.md](https://github.com/brenoleonhardt/tapc/blob/master/README.md), [tapc_prop.h](https://github.com/brenoleonhardt/tapc/blob/master/tapc_prop.h)).

**Generation (stream-based).** "The extension does **not** generate values directly. Instead, it maintains a **byte stream** (a `uint8_t` array) and a **chunk table**"; the generator reads with `tap_read_int32()`, `tap_read_uint16()`, `tap_read_bytes(len)`, `tap_read_str(min, max)` from "an implicit global stream; the user never passes a context pointer", allocating from an arena via `tap_alloc`; each read appends `{type, offset, length}` to the chunk table ([DESIGN.md](https://github.com/brenoleonhardt/tapc/blob/master/DESIGN.md)). "ALL data your generator produces comes from the stream. Lengths, values, and content are all derived from stream bytes ... never from the PRNG" ([tapc_prop.h](https://github.com/brenoleonhardt/tapc/blob/master/tapc_prop.h)). An edge-case bias (`tap_edge_bias_percent`, default 20) substitutes values like `{0, 1, -1, INT32_MIN, INT32_MAX}` ([tapc_prop.h](https://github.com/brenoleonhardt/tapc/blob/master/tapc_prop.h)). Default stream size 65536 bytes, fixed seed by default ([README.md](https://github.com/brenoleonhardt/tapc/blob/master/README.md)).

**Shrinking.** Per chunk, type-specific: `INT32` tries `0, 1, -1, INT32_MIN, INT32_MAX` then halves toward 0; unsigned types try `0, 1, MAX` then halve; lengths try 0 then halve; bytes are zeroed/truncated; "Edge values are only attempted if they are closer to zero than the current value, preventing oscillation"; after any successful shrink the outer loop restarts over all chunks, stopping when a full pass makes no progress ([DESIGN.md](https://github.com/brenoleonhardt/tapc/blob/master/DESIGN.md), [tapc_prop.h](https://github.com/brenoleonhardt/tapc/blob/master/tapc_prop.h)).

**Crashing test cases.** Not handled; the header includes only `<stdint.h> <stddef.h> <stdbool.h> <float.h> <stdio.h> <stdlib.h> <string.h>` and has no signal or process code ([tapc_prop.h](https://github.com/brenoleonhardt/tapc/blob/master/tapc_prop.h)).

**Windows.** Design goal "Cross-platform: Works on any platform with a C99 compiler and `stdout` / `stderr`" ([DESIGN.md](https://github.com/brenoleonhardt/tapc/blob/master/DESIGN.md)); no MSVC CI is present in the repo listing ([GitHub API contents](https://api.github.com/repos/brenoleonhardt/tapc/contents)).

**Licence / maintenance.** MIT ([README.md](https://github.com/brenoleonhardt/tapc/blob/master/README.md)); version 0.2.1 dated 2026-06-22 ([CHANGELOG.md](https://github.com/brenoleonhardt/tapc/blob/master/CHANGELOG.md)); created 2026-06-21, last push 2026-06-22, 1 star ([GitHub API](https://api.github.com/repos/brenoleonhardt/tapc)).

## Hegel (C ABI to a Hypothesis-based engine)

Hegel "is a universal property-based testing engine and family of libraries, built on Hypothesis" ([hegel.dev](https://hegel.dev)). Two C artefacts exist.

**gburd/hegel-c (deprecated).** "a C99 property-based testing library ... based on Hypothesis, using the Hegel protocol"; it "spawns the `hegel` server as a subprocess" and talks to it over stdin/stdout. Its API is draw-based: `static void my_test(hegel_test_case *tc, void *user_data) { int64_t val = hegel_draw_int(tc, hegel_integers(0, 100)); ... }` run by `hegel_run_test(s, my_test, NULL, &settings)`, with combinators `hegel_map`, `hegel_flat_map`, `hegel_filter`, `hegel_one_of`, `hegel_optional` and helpers `hegel_assume`, `hegel_target`, `hegel_note`. The README banner says "This repository is deprecated and read-only ... The protocol it implements has been removed upstream" ([README.md](https://github.com/gburd/hegel-c/blob/main/README.md)); the repo is archived, last push 2026-07-08 ([GitHub API](https://api.github.com/repos/gburd/hegel-c)). The old subprocess protocol (20-byte packet header, CBOR payloads, `generate`/`start_span`/`mark_complete` commands) is specified in [hegel-core docs/library-api.md](https://github.com/hegeldev/hegel-core/blob/main/docs/library-api.md).

**hegeldev/hegel-rust/hegel-c (official).** "C-ABI bindings for hegel's native property-based testing engine", shipped as prebuilt `libhegel-<os>-<arch>` shared and static libraries plus `hegel.h` for `linux/amd64`, `linux/arm64`, `darwin/arm64`, `windows/amd64`, and `windows/arm64` ([hegel-c/README.md](https://github.com/hegeldev/hegel-rust/blob/main/hegel-c/README.md)). The header states "libhegel implements the core of property-based testing: generation, shrinking, the example database, and the decision of what to run next. It ships as a shared library (libhegel.so, libhegel.dylib, hegel.dll) with a C ABI" and defines the vocabulary Run, Test case, Span ("a labeled grouping of draws that tells the shrinker which draws belong to one unit"), and Reproduce blob ("a base64 string encoding a test case's choice sequence, which can be replayed later to reproduce it exactly") ([hegel.h](https://github.com/hegeldev/hegel-rust/blob/main/hegel-c/include/hegel.h)). The caller drives the loop: `hegel_run_start(ctx, settings, callback, user_data, &run)`, then repeated `hegel_next_test_case(ctx, run, &tc)` until it yields NULL, drawing inside the body with e.g. `hegel_generate_integer(ctx, tc, min, max, &out)` which returns `HEGEL_OK` or `HEGEL_E_STOP_TEST` ("libhegel has exhausted its choice budget for this test case and wants the caller to abort the body and return"), marking each case `HEGEL_STATUS_VALID`, `INVALID`, `OVERRUN`, or `INTERESTING`, and finally `hegel_run_result` ([hegel.h](https://github.com/hegeldev/hegel-rust/blob/main/hegel-c/include/hegel.h)). Settings include seed, derandomize, database path/key for persisted counterexamples, and phase flags such as `HEGEL_PHASE_SHRINK` ([hegel.h](https://github.com/hegeldev/hegel-rust/blob/main/hegel-c/include/hegel.h)). The engine is in-process and thread-constrained ("A context must not be used concurrently from multiple threads"); the header documents no crash or timeout handling, so a crashing body takes the engine down with it ([hegel.h](https://github.com/hegeldev/hegel-rust/blob/main/hegel-c/include/hegel.h)). Licence MIT, "Copyright (c) 2026 Antithesis, LLC" ([LICENSE](https://github.com/hegeldev/hegel-rust/blob/main/LICENSE)); crate version 0.37.5 ([hegel-c/Cargo.toml](https://github.com/hegeldev/hegel-rust/blob/main/hegel-c/Cargo.toml)).

Relevance to qc: Hegel is not a C property-testing library but an engine a C frontend could wrap; its handle-based `run -> next_test_case -> draw -> status` loop and its span/reproduce-blob vocabulary are a worked example of exposing a Hypothesis-style engine through a C99-compatible ABI.

## DeepState (Trail of Bits)

Repository: https://github.com/trailofbits/deepstate. "DeepState is a framework that provides C and C++ developers with a common interface to various symbolic execution and fuzzing engines. Users can write one test harness using a Google Test-like API" ([README.md](https://github.com/trailofbits/deepstate/blob/master/README.md)). Included because jmid/pbt-frameworks lists it alongside theft as the C entries with shrinking ([pbt-frameworks README](https://github.com/jmid/pbt-frameworks/blob/main/README.md)).

**Properties and generation.** Tests are `TEST(Unit, Name)` bodies drawing symbolic values with `DeepState_Int()`, `DeepState_IntInRange(low, high)`, `DeepState_CStr_C(len, allowed)`, `DeepState_Malloc`, constrained with `DeepState_Assume(x)` and checked with `ASSERT_*` ([DeepState.h](https://github.com/trailofbits/deepstate/blob/master/src/include/deepstate/DeepState.h)). All draws read sequential bytes from a fixed buffer `DeepState_Input[DEEPSTATE_SIZE]` (default 32768) at `DeepState_InputIndex`; in `--fuzz` mode bytes are filled from `rand()`, and exhausting the buffer calls `DeepState_Abandon("Exceeded set input limit...")` ([DeepState.h](https://github.com/trailofbits/deepstate/blob/master/src/include/deepstate/DeepState.h), [DeepState.c](https://github.com/trailofbits/deepstate/blob/master/src/lib/DeepState.c)).

**Shrinking.** Not in the library; test case reduction is an external tool described in the linked post "Everything You Ever Wanted To Know About Test-Case Reduction, But Didn't Know to Ask" ([README.md](https://github.com/trailofbits/deepstate/blob/master/README.md)).

**Crashing test cases.** Isolated per test by default: `DEFINE_bool(fork, AnalysisGroup, true, "Fork when running a test.")` ([DeepState.c](https://github.com/trailofbits/deepstate/blob/master/src/lib/DeepState.c)). Verdicts are exit codes `DeepState_TestRunPass = 0, Fail = 1, Crash = 2, Abandon = 3` ([DeepState.h](https://github.com/trailofbits/deepstate/blob/master/src/include/deepstate/DeepState.h)). On Unix `DeepState_ForkAndRunTest` does `fork()`, the child runs the test and exits with the verdict, the parent `waitpid`s and returns `WEXITSTATUS` if `WIFEXITED`, else "the test failed due to a crash" ([DeepState_UNIX.c](https://github.com/trailofbits/deepstate/blob/master/src/lib/DeepState_UNIX.c)). On Windows `DeepState_RunTestWin` re-spawns the current executable with `CreateProcess` using `GetModuleFileName` plus `--direct_run --input_which_test <name>`, waits with `WaitForSingleObject`, reads `GetExitCodeProcess`, and treats any exit code other than `DeepState_TestRunPass` as `DeepState_TestRunCrash` ([DeepState_Win32.c](https://github.com/trailofbits/deepstate/blob/master/src/lib/DeepState_Win32.c)). A brute-force fuzz loop runs until a wall-clock `--timeout` (default 3600 s) ([DeepState.c](https://github.com/trailofbits/deepstate/blob/master/src/lib/DeepState.c)).

**Windows.** "DeepState currently targets Linux, Windows, with macOS support in progress ... No current support for ARM64 architecture, this includes Apple Silicon processors"; the Windows build instructions use MinGW under MSYS2 rather than MSVC ([README.md](https://github.com/trailofbits/deepstate/blob/master/README.md)); the `--direct_run` flag is compiled under `#if defined(_WIN32) || defined(_MSC_VER)` ([DeepState.c](https://github.com/trailofbits/deepstate/blob/master/src/lib/DeepState.c)).

**Licence / maintenance.** Apache-2.0 ([README.md](https://github.com/trailofbits/deepstate/blob/master/README.md)); last push 2025-08-22, 862 stars ([GitHub API](https://api.github.com/repos/trailofbits/deepstate)).

## RapidCheck (C++): API shapes that survive translation to C99

Repository: https://github.com/emil-e/rapidcheck. BSD 2-Clause, "Copyright (c) 2014-2015, Emil Eriksson" ([LICENSE.md](https://github.com/emil-e/rapidcheck/blob/master/LICENSE.md)); no tags or releases ([tags](https://github.com/emil-e/rapidcheck/tags)); last commit 2026-08-06 ([commits](https://github.com/emil-e/rapidcheck/commits/master)); CI "using Clang 3.5, GCC 4.9 and Visual Studio 2015" ([README.md](https://github.com/emil-e/rapidcheck/blob/master/README.md)).

- **Property as a callable with a description.** `rc::check("double reversal yields the original value", [](const std::vector<int> &l0) { ... RC_ASSERT(l0 == l1); })`; return type `void` (fail by assertion) or `bool` ([README.md](https://github.com/emil-e/rapidcheck/blob/master/README.md), [doc/properties.md](https://github.com/emil-e/rapidcheck/blob/master/doc/properties.md)). The C99 equivalent is a `void prop(qc_t *)` function plus a name string; parameter-type-driven generation does not translate.
- **Drawing inside the body.** "To explicitly use a generator in your property, use the prefix `*` operator ... This overload returns a value of `T` that was either generated from the given generator or found by shrinking a generated value", and later draws may depend on earlier ones: `const auto max = *rc::gen::arbitrary<int>(); const auto i = *rc::gen::inRange(0, max);` ([doc/generators.md](https://github.com/emil-e/rapidcheck/blob/master/doc/generators.md)). This is the draw-based shape qc wants; `*gen` becomes `qc_draw_int(t, gen)`.
- **Preconditions and outcomes.** `RC_PRE(expr)` discards the case, `RC_DISCARD(msg)`, `RC_FAIL(msg)`, `RC_SUCCEED_IF(expr)`, `RC_ASSERT`; the run "gives up" after `max_discard_ratio` (default 10) discards per success ([doc/assertions.md](https://github.com/emil-e/rapidcheck/blob/master/doc/assertions.md), [doc/properties.md](https://github.com/emil-e/rapidcheck/blob/master/doc/properties.md)). Note "The assertion macros are implemented using exceptions", which has no C99 analogue; a C port needs either return codes or `longjmp` ([doc/assertions.md](https://github.com/emil-e/rapidcheck/blob/master/doc/assertions.md)).
- **Generator combinators worth naming the same way.** `inRange(min, max)`, `just`, `element(...)`, `elementOf(container)`, `oneOf(gens...)`, `weightedOneOf`, `suchThat(gen, pred)`, `map`, `mapcat`, `tuple`, `container`, `nonEmpty`, `unique`, `resize`/`scale`/`withSize`, `noShrink`, `shrink(gen, fn)` ([doc/generators_ref.md](https://github.com/emil-e/rapidcheck/blob/master/doc/generators_ref.md)).
- **Size parameter.** "Generators in RapidCheck have an implicit size parameter ... it starts with a zero size and increases it up to the maximum configured limit for the final test" (`max_size` default 100) ([doc/generators.md](https://github.com/emil-e/rapidcheck/blob/master/doc/generators.md), [doc/configuration.md](https://github.com/emil-e/rapidcheck/blob/master/doc/configuration.md)).
- **Named draws in the counterexample.** `gen.as("index into elements")` replaces the type name with the label when printing ([doc/generators.md](https://github.com/emil-e/rapidcheck/blob/master/doc/generators.md)). Cheap to offer in C as an optional label argument.
- **Shrinking model.** `Shrinkable<T>` is "a value of `T` combined with a tree of possible ways of shrinking it, not just a list", searched recursively ([doc/Shrinkable.md](https://github.com/emil-e/rapidcheck/blob/master/doc/Shrinkable.md)). This lazy-tree design depends on closures and templates; qc's choice-sequence shrinking is the C-compatible alternative.
- **Reproduction.** `RC_PARAMS="seed=..."` reruns identically; `RC_PARAMS="reproduce=<opaque>"` "will only run the failing test case and will immediately find the minimal test case without having to try shrinks known to not produce the failure"; `rc::beforeMinimalTestCase` is a breakpoint hook; `RC_LOG` output is printed only on failure ([doc/debugging.md](https://github.com/emil-e/rapidcheck/blob/master/doc/debugging.md), [doc/configuration.md](https://github.com/emil-e/rapidcheck/blob/master/doc/configuration.md)).
- **Crashes.** No mechanism; the docs mention only exceptions as the failure channel ([doc/gtest.md](https://github.com/emil-e/rapidcheck/blob/master/doc/gtest.md)).

## Proptest (Rust): API shapes that survive translation to C99

Repository: https://github.com/proptest-rs/proptest. Apache-2.0 per repository metadata; last push 2026-08-21; 2230 stars ([GitHub API](https://api.github.com/repos/proptest-rs/proptest)); version 1.11.0 published 2026-03-24 ([crates.io](https://crates.io/api/v1/crates/proptest/versions)).

- **Property declaration.** `proptest! { #[test] fn test_add(a in 0..1000i32, b in 0..1000i32) { ... } }` desugars to constructing a `TestRunner`, grouping the strategies into a tuple, and running a closure that destructures the tuple ([tutorial/macro-proptest.md](https://github.com/proptest-rs/proptest/blob/main/book/src/proptest/tutorial/macro-proptest.md)). Without the macro: `runner.run(&(0..10000i32), |v| { some_function(v); Ok(()) })` and the failure comes back as `TestError::Fail(_, value)` ([tutorial/test-runner.md](https://github.com/proptest-rs/proptest/blob/main/book/src/proptest/tutorial/test-runner.md)). The explicit-runner form maps directly onto a C API (`qc_run(&config, prop)`).
- **Strategy = generate + shrink.** "A strategy defines two things: How to generate random values ... How to 'shrink' such values into 'simpler' forms"; `new_tree()` yields a `ValueTree` with `current()`, `simplify()`, `complicate()` "which together allow binary searching over the input space" ([tutorial/strategy-basics.md](https://github.com/proptest-rs/proptest/blob/main/book/src/proptest/tutorial/strategy-basics.md), [tutorial/shrinking-basics.md](https://github.com/proptest-rs/proptest/blob/main/book/src/proptest/tutorial/shrinking-basics.md)). "Note that shrinking never shrinks a value to something outside the range the strategy describes" ([tutorial/shrinking-basics.md](https://github.com/proptest-rs/proptest/blob/main/book/src/proptest/tutorial/shrinking-basics.md)); a property qc's typed choices should preserve.
- **Combinators.** `prop_map` ("shrinking occurs in terms of `u32`, even though we're generating a `String`"), `prop_flat_map` for dependent draws ("proptest still understands the connection to the original strategy and will shrink `vec` as well. All the while, `index` continues to be a valid index"), `prop_filter`, `prop_oneof`, `Just`, `prop::collection::vec(elem, 1..100)`, `any::<T>()` via `Arbitrary` ([tutorial/transforming-strategies.md](https://github.com/proptest-rs/proptest/blob/main/book/src/proptest/tutorial/transforming-strategies.md), [tutorial/higher-order.md](https://github.com/proptest-rs/proptest/blob/main/book/src/proptest/tutorial/higher-order.md), [tutorial/arbitrary.md](https://github.com/proptest-rs/proptest/blob/main/book/src/proptest/tutorial/arbitrary.md)). In C without closures, dependent generation is more naturally expressed by drawing sequentially in the body (`len = draw; idx = draw_in(0, len)`), which is what the choice sequence supports.
- **Configuration knobs.** `cases` (default 256), `max_local_rejects` (65536), `max_shrink_iters` (default `u32::MAX` meaning four times `cases`; 0 disables shrinking), `max_shrink_time` (ms), `fork: bool`, `timeout` (ms; "implicitly enables forking"), `failure_persistence`, `verbose`, `rng_algorithm`, each overridable by a `PROPTEST_*` environment variable ([test_runner/config.rs](https://github.com/proptest-rs/proptest/blob/main/proptest/src/test_runner/config.rs), [tutorial/config.md](https://github.com/proptest-rs/proptest/blob/main/book/src/proptest/tutorial/config.md)).
- **Crashing test cases (fork).** "Forking allows proptest to work with tests which may fail by aborting the process, causing a segmentation fault, etc, but can be a lot slower ... For forking to work correctly, both the `Strategy` and the content of the test case itself must be deterministic" ([test_runner/config.rs](https://github.com/proptest-rs/proptest/blob/main/proptest/src/test_runner/config.rs)). Mechanism: rusty-fork "works by *spawning* a fresh instance of the current process, after adjusting the command-line to ensure that only the desired test is entered", because "While true process forking can be done on Windows, it's neither fast nor reliable" and "The Rust test environment is multi-threaded" ([rusty-fork README](https://github.com/AltSysrq/rusty-fork/blob/master/README.md)). Proptest's supervisor creates a temp "forkfile", passes its path in the `_PROPTEST_FORKFILE` environment variable, and the worker appends each case's outcome to it (`replay::append`, `ping`, `terminate`); after the worker exits the supervisor re-parses the file and, if the worker "crashed or timed out before the first test started running", aborts, otherwise adds "a synthetic failure" for the case in flight and loops, respawning a worker that replays the recorded steps ([test_runner/runner.rs](https://github.com/proptest-rs/proptest/blob/main/proptest/src/test_runner/runner.rs)). A `timeout` fails a case with "Timeout of {} ms exceeded: test took {} ms" even if the case eventually returned ([test_runner/runner.rs](https://github.com/proptest-rs/proptest/blob/main/proptest/src/test_runner/runner.rs)).
- **Failure persistence.** Seeds of failing cases are written under `proptest-regressions/` with the header "Seeds for failure cases proptest has generated in the past. It is automatically read and these particular cases re-run before any novel cases are generated. ... It is recommended to check this file in to source control" ([failure_persistence/file.rs](https://github.com/proptest-rs/proptest/blob/main/proptest/src/test_runner/failure_persistence/file.rs)).
- **Assertions.** `prop_assert!`/`prop_assert_eq!` "doesn't cause a bunch of panic messages to be printed on intermediate test failures", and `prop_assume!` rejects a case ([getting-started](https://proptest-rs.github.io/proptest/proptest/getting-started.html), [tutorial/higher-order.md](https://github.com/proptest-rs/proptest/blob/main/book/src/proptest/tutorial/higher-order.md)). Quiet intermediate failures during shrinking is a report-format lesson for qc.
